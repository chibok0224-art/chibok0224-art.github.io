What a good app maintenance service includes

App maintenance gigs are sold as monthly plans or one-off updates. Check that the service states:

  • Platforms: iOS, Android or both.
  • Updates: operating system and library updates.
  • Bug fixes: how many, or how much time, per month.
  • Monitoring: crash and performance reports.
  • Store compliance: new rules and requirements.
  • Response time for urgent problems.
  • Reporting of work done.

Start with an audit. A new maintainer should review the code, dependencies and store listings first, then give you a list of risks and recommended updates. It sets priorities and shows how well they understand the app before you commit to a monthly plan.

What to prepare before hiring

  1. Source code in a repository you control.
  2. Store accounts, with the maintainer added as a team member.
  3. Backend and hosting access, through separate users.
  4. Known bugs and user complaints.
  5. Build instructions and signing information.
  6. Your plans: new features or just keeping it running.

If you do not have the source code or signing keys, sort that out first. Without them, even a simple update can become impossible, and recovering access can take time.

Read your recent reviews with the maintainer. Users often describe bugs and missing features in reviews, and fixing the most common complaints can quickly improve ratings.

Agree on a simple release routine: changes are tested on a test build, you approve them, and only then are they submitted to the stores. Store reviews can take time, so urgent fixes need planning too. A clear routine prevents rushed releases that introduce new bugs while fixing old ones, and it tells you exactly when each update will reach users.

What drives the price

  • number of platforms
  • size and age of the code
  • frequency of updates
  • monitoring and response times
  • backend maintenance
  • new features beyond maintenance

An older app built with outdated tools may need a larger upfront update before routine maintenance is possible. Ask for this to be estimated separately.

Red flags

  • No access to the source code or store accounts.
  • Updates published without testing.
  • No reports of what was done each month.
  • Unclear response times for outages.
  • Requests for your main passwords.

Keep test devices or testers for both old and new phones. Many maintenance problems appear only on specific versions or screen sizes.

Quick pre-order checklist

  • I have the source code, keys and store accounts.
  • The maintainer will start with an audit.
  • The plan covers updates, fixes and monitoring.
  • Response times for urgent issues are agreed.
  • I will receive a monthly report of work done.
